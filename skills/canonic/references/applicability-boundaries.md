# Applicability Boundaries

## ICM Is A Good Fit For
- sequential workflows;
- repeatable processes;
- reviewable intermediate outputs;
- human intervention between stages;
- repeated execution with new inputs;
- file-first knowledge work;
- traceable transformations;
- projects where context can be loaded selectively.

## ICM Is A Poor Fit For
- real-time multi-agent collaboration;
- high concurrency among many users;
- large-scale processing queues;
- complex automatic branching;
- extremely low-latency responses;
- distributed transactional state;
- continuous dynamic coordination between agents.

When ICM is not a good fit, say so clearly and recommend a simpler or more appropriate architecture.
