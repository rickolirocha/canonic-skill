# Audit Checklist

Use evidence. Do not produce generic criticism without paths.

## Structure
- Is the root understandable?
- Is there a clear entry point?
- Is the sequence explicit?
- Does numbering represent real order?
- Does each folder have a recognizable function?
- Are there empty or decorative folders?
- Are there permanent `misc`, `general`, `other`, or `temp` dumps?

## Context
- Is global context separate from local context?
- Are context files routers instead of giant deposits?
- Are rules duplicated?
- Are instructions conflicting?
- Does the agent know what to load?
- Do large files identify relevant sections?
- Is file authority explicit?

## Layers
- Are Layer 3 and Layer 4 separate?
- Are stable references mixed with current outputs?
- Are old outputs being used as rules without approval?
- Is the current working artifact identifiable?
- Does each stage know which previous output to consume?

## Stages
- Does each stage have one primary responsibility?
- Are inputs explicit?
- Are outputs explicit?
- Is the handoff readable?
- Is completion objective?
- Is human review present where needed?
- Is the stage doing too much?
- Are any stages not transforming anything?

## Fidelity
- Can output be traced to source?
- Is the original source preserved?
- Are summaries separate from originals?
- Are inferences presented as facts?
- Are human edits used as signals without becoming automatic rules?

## Reuse
- Does repeated material deserve a template?
- Does repeated cross-project work deserve a skill?
- Does mechanical work deserve a script?
- Was a local rule globalized too early?
- Does a global skill contain client-specific context?

## Complexity
- Does the architecture solve a real problem?
- Could agents be stages?
- Is automation premature?
- Could folder structure replace orchestration code?
- Is the system sophisticated before being executed?
